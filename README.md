# q3-issue-agent

집계 지표에 속지 않고, **진짜로 심각한 문제 '하나'만 근거와 함께 제안**하는 CLI 에이전트.
동네 기반 구인구직 매칭 퍼널(공고 → 지원 → 매칭)의 합성 데이터 위에서 동작한다.

```
python3 run.py  # 생성 → 탐지 → 채점 한 방 (파이썬 표준 라이브러리만, 설치 불필요)
```

## 결과

| 검사 | 결과 |
|---|---|
| 함정 데이터 15개 시드 (42–46, 100–109) | **정탐 15 / 오탐 0 / 미탐 0** (primary 적중 13) |
| 클린 데이터 20개 시드 (42–61) | **헛제안 0** |
| 격리 가드 | 탐지기에 정답 참조 코드를 넣으면 채점 거부 (exit 2) |

primary 미적중 2건(시드 43·46)은 T1의 실현 신호가 우연히 약하게 뽑힌 시드다. 탐지기가 실현 데이터 기준으로 더 심각한 다른 함정(T2)을 고른 정당한 판단이며, 판정 근거는 `DECISIONS.md`에 있다.

## 실제로 무엇을 제안하나

시드 42 실행 시 `out/report.md`가 내놓는 제안이다.

> **5km 이상 거리 지원자의 노쇼율이 9.4%(n=159)에서 28.8%(n=330)로 악화.**
> 전체 노쇼율은 7.8% → 9.8%로만 움직여, 전체 추세로 설명되지 않는 초과 악화가 **17.3%p**.
> **확인 액션:** 해당 구간 노쇼 매칭 64건 중 50건을 표본으로 뽑아 채팅 로그로 사유를 분류할 것.

같은 리포트에 **폐기한 후보와 그 사유**도 함께 남는다.

- 야탑동 재이용률 43.4% → 23.2% : 동일 세그먼트 상류 지표 악화의 기계적 파생으로 판단해 폐기
- 야탑동 지원→매칭 전환율 12.5% → 4.5% : 심각도 점수 열세 (0.1349 vs 1위 0.4285)
- 주방·주말 1시간 내 매칭률 60.2% → 19.6% : 심각도 점수 열세 (0.0304)

집계 지표만 보면 노쇼율은 7.8% → 9.8%로 2%p 오른 정도라 눈에 띄지 않는다. 구간 비중이 작아 평균에 묻히기 때문이다.

## 어떻게 동작하나

세 부분을 서로 격리한 채 실행한다.

**1. 생성기** (`src/gen/`)
8주치 데이터를 만들고 "집계는 개선처럼 보이는데 특정 세그먼트가 곪은" 함정 3개를 심는다. 정답은 `answers/ground_truth.json`에 기록한다. (재생성 가능한 산출물이므로 저장소에는 포함하지 않는다)

**2. 탐지기** (`src/agent/`)
세그먼트 × 기간별 지표를 결정론적으로 집계하고, 표면 지표와 세그먼트 지표의 괴리를 스캔해 후보를 추린 뒤 단 하나로 좁힌다. **정답 파일에 접근할 수 없다.**

**3. 채점기** (`score.py`)
제안을 정답과 대조해 정탐·오탐·미탐을 판정한다. 채점 전에 탐지기 소스가 정답 쪽을 참조하지 않는지 정적 검사하고, 위반이 발견되면 채점을 거부한다.

격리를 규칙이 아니라 실행 구조로 강제한 이유는 단순하다. 채점자가 정답을 알면 유리하게 맞추게 되고, 그러면 이 수치는 아무것도 증명하지 못한다.

## 되돌린 판단

설계 과정의 실패·오탐·잘못된 가정 다섯 건을 `FAILURES.md`에 시간순으로 기록했다. 그중 판단을 되돌린 세 건은 다음과 같다.

**임계값을 함정 크기에 맞추려던 순환**
표본 노이즈를 근거로 절대폭 임계를 5pp에서 8pp로 올리는 안을 검토하다가, "8pp면 T2가 경계선에 걸려 미탐될 수 있다"는 이유로 다시 조정하려 했다. 이건 함정의 정답 크기를 아는 채로 규칙을 정답에 맞추는 순환이라, 격리로 막으려던 오류를 규칙 설계 단계에서 되풀이할 뻔했다. 최종 임계는 "매칭 퍼널에서 5pp는 액션을 요하는 크기"라는 제품 기준에서 도출했고, 노이즈 통제는 표본 조건(MIN_N=50)으로 역할을 분리했다. 이후 임계 조정의 근거는 실측된 오탐·미탐으로만 삼았다.

**"다른 축으로는 안 샐 것"이라는 예측이 반증됨**
거리 함정이 지역 축으로 새어 보일 가능성은 희석 때문에 낮다고 판단했으나, 5시드 평가에서 오탐 2건이 나왔다(시드 44 백현동 노쇼, 시드 45 주방 노쇼). 분해해 보니 둘 다 5km+ 함정이 구성비 효과로 다른 축에 새어 나간 것이었고, 작은 세그먼트에서는 희석돼도 노이즈와 겹치면 임계를 넘었다. 직접 표준화 검사를 dedup 0단계로 추가해 차단했고, 동일 시드에서 오탐 0이 됐다.

**"통계 검정은 과하다"는 판단이 두 단계로 반증됨**
고정 임계와 표본 하한이면 충분하다고 봤으나, 클린 데이터 참음성 검사에서 10시드 중 5회 헛제안이 나왔다. 회당 100건 넘는 검정을 하니 다중 비교로 우연이 매번 몇 개씩 생긴 것이다. Bonferroni로 고치자 헛제안은 0이 됐지만 primary 적중이 14/15에서 9/15로 떨어졌다. T1의 실현 신호(z≈3.0~3.3)가 정확히 Bonferroni 임계(z≈3.35)에 걸린 것으로, FWER 통제가 '발견' 문제에 과보수적이라는 교과서적 함정을 그대로 밟았다. Benjamini-Hochberg(FDR, α=0.05)로 교체하니 강한 진짜 신호가 있을 때 임계가 적응적으로 올라가 경계 신호를 살리면서, 신호 없는 데이터에서는 헛제안 0을 유지했다.

나머지 두 건은 함정 설계의 전제가 데이터로 깨진 사례다. "함정을 심어도 집계 지표는 안 움직일 것"이라는 가정이 반증되면서, 탐지 규칙을 '전체 지표가 정상일 것'이 아니라 **세그먼트 악화와 전체 악화의 초과분**으로 정의하게 됐다. 현실에서도 곪은 세그먼트는 집계에 일부 새어 나오므로, 본질은 '집계의 무결'이 아니라 '괴리'다.

## 탐지 로직

**기간 비교**: 전반 4주(baseline) vs 후반 4주(current)
**축**: 지역 / 직종 / 평일·주말 / 거리 구간 / 직종 × 요일

**후보 조건** (전부 충족해야 통과)

- 절대 악화 ≥ 5pp
- 초과 악화(전체 추세 대비) ≥ 5pp
- 상대 악화 ≥ 30%
- 표본 ≥ 50
- BH(FDR α=0.05) 유의성 통과

**중복 제거**

1. 직접 표준화로 다른 축 구성비로 설명되는 악화를 폐기
2. 같은 세그먼트의 여러 지표는 퍼널 상류를 대표로
3. 2차원 축과 그 성분 축의 중복 제거

남은 후보는 심각도 점수(상대 악화 × 볼륨 비중 × 지표 가중치)로 하나만 남긴다.

## 원칙

**수치는 전부 코드가 계산한다.**
LLM은 규칙 설계 단계에만 개입했고, 그 추론과 실패는 `DECISIONS.md`·`FAILURES.md`에 남겼다. 실행 파이프라인은 100% 결정론적이며, 리포트의 서술은 템플릿이고 모든 숫자는 코드 산출값의 인용이다.

**정답과 탐지기를 격리한다.**
함정 파라미터는 `src/gen/traps.py`에만 존재하고, `answers/`는 채점기만 읽는다. 이름 계약(`src/contract.py`)은 축·지표 어휘만 공유한다.

**문제는 하나만 올린다.**
많이 잡는 것보다 평균에 속지 않는 것이 목적이다. 폐기한 후보와 사유를 함께 남겨 판단을 검증 가능하게 한다.

## 재현

```
python3 run.py                  # 생성 → 탐지 → 채점 한 방 (시드 42)
python3 run.py --eval-seeds 5   # 시드 5개 반복 채점 → 정탐률·오탐률 집계
python3 run.py --clean-seeds 5  # 함정 없는 데이터 참음성 확인 (헛제안 0이어야 정상)
```


산출물: `out/report.md`(사람용 리포트) · `out/proposal.json`(채점용) · `out/score.json`(채점 결과)

## 구조

```
run.py                 # 원커맨드 실행기
score.py               # 독립 채점기 (answers/를 읽는 유일한 소비자 + 격리 가드)
src/contract.py        # 이름 계약 (축·지표 어휘만, 함정 정보 없음)
src/gen/generate.py    # 기간 대칭 베이스 데이터 생성
src/gen/traps.py       # 함정 주입 + 정답 기록
src/agent/metrics.py   # 세그먼트 × 기간 지표 집계
src/agent/rules.py     # 괴리 스캔 (임계값 + BH 유의성)
src/agent/severity.py  # 심각도 점수 · 중복 제거 · 최종 1개 선택
src/agent/report.py    # proposal.json + report.md 생성
```

## 한계 / 범위 밖

- **합성 데이터**다. 실서비스 데이터를 쓸 수 없어 매칭 퍼널을 직접 설계했고, 탐지 성공을 채점하려면 정답을 알아야 하므로 함정을 심었다.
- 심슨의 역설(mix-shift) 함정은 보류했다. 핵심인 "평균에 가려진 세그먼트 악화 탐지"를 먼저 확실히 하기 위해서다.
- 대시보드, 실시간 처리, 예측 모델링, 다중 문제 제안은 의도적으로 범위 밖이다.
